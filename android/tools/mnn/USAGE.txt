Gemos Still: original-resolution SHARP rest-stage diagnostic

This is an ordinary ARM64 Android shell executable, not an APK or production
inference engine. Building does not install or run anything on a phone. Model
weights, photos, feature tensors, and private device identifiers are not included.

Pinned MNN: dbf9ba61b08106a3b43426e295d1a29cb41cc8fe (3.6.1)
The build includes OpenCL in one libMNN.so. Keep gemos-rest-probe, libMNN.so,
and libc++_shared.so together. Their RUNPATH is $ORIGIN. Preserve LICENSE.*
and THIRD-PARTY-NOTICES.txt when distributing the diagnostic bundle.

Capability query, without loading a model:
  ./gemos-rest-probe --backend opencl --capabilities-only

One inference, after a separate reviewed memory/temperature admission:
  ./gemos-rest-probe --backend opencl --stage rest --model MODEL.mnn \
    --weights MODEL.mnn.weight --inputs INPUT_DIRECTORY --output OUTPUT_DIRECTORY

The default stage is rest. --stage depth and --stage gaussian select the two
separately validated parts of that same graph. Print a fixed stage contract
without loading a model or GPU:
  ./gemos-rest-probe --stage depth --print-contract
  ./gemos-rest-probe --stage gaussian --print-contract
stdout is newline-delimited JSON, beginning with the diagnostic process PID.

Three additional fixed research profiles split depth itself at two original
decoder tensors, preserving every original operation and parameter:
  depth-coarse: spn_latent1, spn_high, spn_middle, spn_low, spn_image_global
                -> depth_decoder_features.f32 [1,256,384,384], exactly
                150,994,944 raw FP32 bytes (144 MiB).
  depth-refine: depth_decoder_features.f32 and original spn_latent0.f32
                -> depth_head_features.f32 [1,128,768,768], exactly
                301,989,888 raw FP32 bytes (288 MiB).
  depth-fine:   only depth_head_features.f32 -> clamped_monodepth_disparity.f32
                [1,2,1536,1536]. There are no additional skip inputs.
Use the same explicit --model/--weights/--inputs/--output arguments and separate
child processes. The intermediate must come from the same photo's coarse run.
Keep spn_latent0 from the same photo for refine; it is not an input to coarse.
The coarse->refine head tensor is bitwise equal to the previous two-part depth
head tensor, whose unchanged fine stage already produced bitwise equal depth.
Refine schedules the independent latent0 skip branch first. Every individual
MNN operator's serialized content, weight offset and tensor index is unchanged;
the validated change only reorders that topologically independent branch.

These extra profiles have not established mobile fit. The original full-depth
OpenCL session hit the unchanged 1536-MiB RSS guard during session creation.
The three-way split removes 768px activations from coarse, but refine and fine
still process large original features. Static FP16 activation estimates exclude
driver/workspace/allocator costs and cannot establish mobile fit. The reordered
refine desktop CPU run used 2033.79 MB of session memory and 2.162 GiB peak RSS;
this is not a phone GPU memory measurement. Keep every original guard and require
separate memory admission/numerical validation; do not treat this split as a
successful phone run or automatically retry a guarded failure.

CPU comparison uses --backend cpu. It retains the same conservative Android
limits and is not permission to attempt the known multi-gigabyte CPU pipeline.

All tensor files are little-endian float32 in NCHW layout. The rest profile
requires exactly these eight named inputs:
  image.f32            [1,3,1536,1536], RGB [0,1]
  disparity_factor.f32 [1]
  spn_latent0.f32      [1,1024,96,96]
  spn_latent1.f32      [1,1024,96,96]
  spn_high.f32         [1,1024,96,96]
  spn_middle.f32       [1,1024,48,48]
  spn_low.f32          [1,1024,24,24]
  spn_image_global.f32 [1,1024,24,24]
The six features must come from the original 384px ViTs and original overlapping
pyramid merge, before the SPN upsample modules. The model remains 1536px and
produces 1,179,648 Gaussians. Arbitrary renamed tensors are not interchangeable.

The depth profile requires only the six spn_*.f32 feature files above. Its only
output is clamped_monodepth_disparity.f32 [1,2,1536,1536] (18,874,368 bytes),
the original two-channel monodepth head after the original Clip. No new depth
sorting, normalization or resolution change is introduced. The original model
sets sorting_monodepth=False and decoder_features=False.

The gaussian profile requires the original eight inputs plus that depth output
under exactly the same clamped_monodepth_disparity.f32 filename. Its original SPN
upsamplers run again to reduce concurrently live memory; the Gaussian graph
does not consume large DPT decoder features. The desktop CPU chain was bitwise
equal to the full-rest MNN graph for all five outputs. This does not establish
mobile GPU numerical accuracy or memory admission.

Use separate child processes, waiting for depth to exit before launching
gaussian so all depth session/runtime allocations have been released:
  ./gemos-rest-probe --backend opencl --stage depth \
    --model MODELS/A-monodepth-fp16.mnn \
    --weights MODELS/A-monodepth-fp16.mnn.weight \
    --inputs DEPTH_INPUTS --output DEPTH_OUTPUT
  # After a successful, independently checked depth run, place its
  # clamped_monodepth_disparity.f32 into GAUSSIAN_INPUTS, then run:
  ./gemos-rest-probe --backend opencl --stage gaussian \
    --model MODELS/B-gaussians-fp16.mnn \
    --weights MODELS/B-gaussians-fp16.mnn.weight \
    --inputs GAUSSIAN_INPUTS --output GAUSSIAN_OUTPUT
The application must use the depth output from the current photo, not a stored
desktop diagnostic fixture. Neither stage automatically invokes the next one.

Each model receives its explicit --weights path via setExternalFile before
session creation. Application model-store fields are depthModel, depthWeights,
gaussianModel, gaussianWeights; corresponding deployment basenames are exactly
A-monodepth-fp16.mnn, A-monodepth-fp16.mnn.weight, B-gaussians-fp16.mnn and
B-gaussians-fp16.mnn.weight. Verify the separately supplied SHA-256 manifest.
The three-way diagnostic deployment basenames are A0-depth-coarse-fp16.mnn,
A1-depth-refine-fp16.mnn and A2-depth-fine-fp16.mnn, each with its explicit
matching .mnn.weight file. These are separate research profiles; the existing
application's two-part model-store fields are not silently reinterpreted.

The Android watchdog exits only this diagnostic process after 60 seconds, RSS
above 1536 MiB, or system MemAvailable below 1024 MiB. An external host watchdog
and current device admission are still required: GPU memory may not appear in
process RSS. There is no root, flashing, private namespace, or device setting API.

Only the public libOpenCL.so name is loaded. The CI source-copy patch removes
MNN's other Android driver names/absolute paths. If public OpenCL is unavailable,
the executable reports failure instead of trying a private driver or CPU.

Backend reports inspect the actual created MNN Execution objects, using read-only
internal headers from the exact pinned revision. Whole-session CPU fallback or
CPU Conv/Deconv/MatMul is rejected before inference in OpenCL mode. Small CPU
shape/reduction/normalization operations are explicitly reported as hybrid; a
hybrid run is never labelled a fully GPU run. Completed operator backend counts
are reported separately from the planned execution coverage.

OpenCL explicitly requests BUFFER memory and disables tuning (mode bits 65).
Precision_Normal (0) in this pinned source uses FP16 storage and FP32 COMPUTE_FLOAT;
pure FP16 arithmetic is not requested. Actual input CL_MEM_TYPE is queried through
the public OpenCL API, with its CL_MEM_CONTEXT checked against the admitted GPU.
The non-owning cl_mem handle bytes are borrowed from the pinned MNN wrapper;
the executable never creates or destroys a C++ OpenCL wrapper and has no static
OpenCL function dependency. All OpenCL calls use public C API function pointers.

Rest and gaussian outputs are mean_vectors_ndc.f32 [1,1179648,3],
singular_values_ndc.f32 [1,1179648,3], quaternions_ndc.f32 [1,1179648,4],
colors.f32 [1,1179648,3] and opacities.f32 [1,1179648]. Every stage also writes
report.json with stage/contract, actual execution backends and output shapes.
A finite result alone does not prove correctness. Compare against the original desktop output, inspect
memory and temperature, and stop before any production integration if these
checks fail. No automatic retry or warmup inference is performed.
